# Full-Stack Audit — Findings & Fixes

**Date:** 2026-08-30
**Scope:** Entire front-end (static HTML pages + shared ES modules) and the client side of the Supabase back-end integration. Follow-up to the previously completed backend audit.
**Not touched:** CI/CD configs, `.env` files, lockfiles, database schema (no migrations added or changed).

**Files changed (17):** `account.html`, `admin.html`, `archive-publish.html`, `archive.js`, `article.html`, `help.html`, `history.html`, `index.html`, `leadership.html`, `login.html`, `nations.js`, `nav.js`, `news-publish.html`, `news.js`, `parental-consent.html`, `shop.html`, `tasks.html`

**Verification:** every inline `<script type="module">` block and every standalone `.js` file was extracted and passed `node --check`. Greps confirm zero double-escaping (`escapeHtml(escapeHtml(`, `esc(esc(`), no `eval` / `new Function` / `document.write`, no secrets in `localStorage`, and no remaining `target="_blank"` without `rel`.

## Security Flaws

### 1. Stored XSS in the public archive renderer — `archive.js` — **Critical**
**Wrong:** the archive index performed *no* HTML escaping at all. Every document title, description, category, author and tag from the database was interpolated straight into `innerHTML`, so anyone able to publish an archive entry could execute script in every visitor's browser.
**Changed:** added `esc()` (escapes `& < > " '`) and `safeUrl()` (allows only `http(s)` and relative URLs), and routed every interpolated field and every `href`/`src` through them.

### 2. Stored XSS across the remaining renderers — **Critical**
**Wrong:** author- and member-supplied text was interpolated into `innerHTML` templates unescaped. Affected fields by file:
- `news.js` — article titles, summaries, categories, author names, image URLs.
- `nations.js` — nation names, descriptions, leaders, seasons, flag file names.
- `article.html` — `title`, `summary`, `category`, `author_name`, `image_url`, formatted date.
- `leadership.html` — `p.name`, `p.title`, `p.subtitle`, plus club-president `name`, `username`, `club_name`, `region`. Public page.
- `history.html` — `s.name`, `s.period`, `s.description`. Public page.
- `shop.html` — cart item names/images/ids, product-detail modal (image, thumbnails, category, name, description, spec labels/values), product grid, and raw `error.message` strings.
- `account.html` — `f.name`, `adminLabel`, message `it.body`, `m.subject`, `lastPreview`/`lastTime`, `minecraft_username`, `discord_id`, `google_id`, `email`, `error.message`.
- `tasks.html` — project names, task titles, tag names, due dates, priorities, role labels and member display names (~20 interpolation sites).
- `news-publish.html` / `archive-publish.html` — titles, categories, author names, status labels, rejection notes, dates.
- `admin.html` — 41 distinct field names across 65 interpolation sites (member usernames, role labels/names/levels, audit actions and actor types, article/document titles and statuses, rejection notes, FAQ questions, permission keys and labels, nation/season/leadership/history names, error messages).

**Changed:** each file now defines (or reuses) an `esc`/`escapeHtml` helper covering `& < > " '`, and every interpolated field is wrapped. In `nav.js` the role-preview banner label is escaped too. Where a value was already escaped at its point of definition (`admin.html` sender/subject/preview/body/adminLabel; `account.html` `lastPreview`/`adminLabel`) it was deliberately left single-escaped, and the five `confirm()`/`prompt()` call sites that render plain text were left unescaped so they do not display literal `&amp;`.

### 3. Attribute-breakout XSS in the add-to-cart payload — `shop.html` — **Critical**
**Wrong:** the product JSON payload sits inside `onclick='shopAddToCart(${prod})'` — a *single*-quoted attribute — but the code escaped only `"`. A product name containing `'` closed the attribute and injected arbitrary JS.
**Changed:** dropped the `.replace(/"/g,'&quot;')` and wrapped both `JSON.stringify(...)` payloads in `esc(...)`, which escapes `'`, `&` and `<` as well.

### 4. `javascript:` URLs reachable from markdown and FAQ links — `article.html`, `news-publish.html`, `archive-publish.html`, `help.html`, `news.js`, `archive.js` — **High**
**Wrong:** markdown link/image URLs and FAQ link targets went into `href`/`src` with no scheme check, so `[click](javascript:...)` executed on click.
**Changed:** added `safeUrl()` (plus `safeLinkUrl()` in `nav.js` and https-only `safeAttachmentUrl()` in `account.html`) that allow-lists `http`/`https` and relative URLs and returns `''` for everything else; links whose URL is rejected now render as plain text. In `help.html` the URL arrives pre-escaped, so it is decoded, scheme-checked, then re-escaped.

### 5. Open redirect on the login page — `login.html` — **High**
**Wrong:** `?return=` was passed unvalidated to `window.location.replace()` and to the OAuth `redirectTo`, turning the login page into an open redirect usable for phishing and for pointing the OAuth callback at an attacker-controlled origin.
**Changed:** added `safeReturnTo()`, which accepts only `"<page>.html"` (optionally with a query or hash) and otherwise falls back to `account.html`.

### 6. Stale authorization check for admin UI — `shop.html` — **High**
**Wrong:** admin controls were gated on the legacy `profiles.role` column, which is no longer authoritative and can diverge from the real role/permission system.
**Changed:** replaced with `await withTimeout(hasPermission('can_view_admin'), 6000)`, failing closed on error — matching every other page.

### 7. CSS / attribute injection via colour fields — `tasks.html`, `account.html`, `admin.html` — **Medium**
**Wrong:** tag and role colours are free text in the database but land inside `style="..."`, so a crafted value could close the attribute or inject arbitrary CSS (overlay/clickjacking, remote-URL background requests).
**Changed:** added `safeColor()` — `/^#[0-9a-fA-F]{3,8}$/`, defaulting to `#888888` — applied to all colour slots (4 tag-colour sites and 11 background/foreground slots in `tasks.html`, 4 role-chip slots in `account.html`, 5 in `admin.html`).

### 8. PostgREST `.or()` filter injection in the audit log — `admin.html` — **Medium**
**Wrong:** the audit-log search term was concatenated into a PostgREST `.or()` filter string. `,` `(` `)` `.` `*` are filter grammar, so a term containing them either broke the query (HTTP 400) or silently widened it beyond the intended columns.
**Changed:** grammar characters are stripped from the term before interpolation, and an empty result skips the filter entirely.

### 9. Reverse tabnabbing on external links — `index.html`, `login.html`, `parental-consent.html`, `nav.js`, `help.html` — **Low**
**Wrong:** `target="_blank"` links (hero Discord button, policy links, nav Discord/YouTube links, FAQ links) lacked `rel="noopener"`, letting the opened page reach back through `window.opener`.
**Changed:** added `rel="noopener noreferrer"` (or `rel="noopener"` for first-party pages) to every such link; a sweep confirms none remain.

### 10. Weak email validation on signup — `login.html` — **Low**
**Wrong:** signup only checked `if (!email)`, so obviously malformed addresses were sent to the server and failed opaquely.
**Changed:** validates against `/^[^\s@]+@[^\s@.]+(\.[^\s@.]+)+$/` before submitting.

## UI Bugs

### 11. Markdown images never rendered — `article.html`, `news-publish.html`, `archive-publish.html` — **High**
**Wrong:** the link rule `\[([^\]]+)\]\(([^)]+)\)` ran *before* the image rule, so `![alt](url)` was consumed as a link and the leading `!` was left as literal text. No article or archive entry could display an inline image.
**Changed:** the image rule now runs before the link rule in all three renderers.

### 12. Markdown blockquotes never rendered — `article.html`, `news-publish.html`, `archive-publish.html`, `news.js`, `archive.js` — **Medium**
**Wrong:** the escape pass converted `>` to `&gt;` before the blockquote rule tested for `^> `, so the rule could never match and blockquotes rendered as literal `&gt;` text.
**Changed:** the blockquote rule now matches `^&gt; `.

### 13. Quote characters broke markdown output — all five markdown renderers — **Medium**
**Wrong:** the escape pass handled `& < >` but not `"`, so a quote inside body text could terminate an attribute in the generated HTML.
**Changed:** added `.replace(/"/g,'&quot;')` to the escape pass in every renderer.

### 14. Admin bootstrap aborted on a malformed tab name — `admin.html` — **High**
**Wrong:** the URL hash and the `admin-active-tab` value from `localStorage` were fed directly into a `querySelector` template. A value containing a quote produced an invalid selector, threw, and aborted the entire admin bootstrap — a blank admin console.
**Changed:** added `isTabName()` (`/^[a-z0-9-]{1,40}$/i`); anything else is discarded and the default tab loads.

### 15. Wrong share-title fallback — `article.html` — **Low**
**Wrong:** `article.title || article.title` — the fallback repeated the same expression, so an untitled article shared with an empty title.
**Changed:** the fallback is now `'Minecraft Club of America'`.

### 16. Missing `alt` on the header-image preview — `news-publish.html:216` — **Low**
**Wrong:** `<img id="np-image-preview">` had no `alt`, so screen readers announced nothing and a broken URL showed an empty box.
**Changed:** added `alt="Preview of the article header image"`.

## UX Bugs

### 17. Signup button stuck on "Sending…" after a network error — `login.html` — **High**
**Wrong:** the signup `fetch` had no `catch`. If the request failed (offline, DNS, edge function down) the promise rejected, the button stayed disabled reading "Sending…", and the user had to reload the page with no explanation.
**Changed:** wrapped in `try/catch` that restores the button state and shows "Could not reach the server. Please try again."

### 18. Audit-log search failed on ordinary punctuation — `admin.html` — **Medium**
**Wrong:** searching for a term containing a comma or period returned an HTTP 400 with no visible message (same root cause as finding 8).
**Changed:** fixed by the same sanitisation — punctuation now degrades to a space instead of breaking the query.

### 19. Product cards were mouse-only — `shop.html` — **Medium**
**Wrong:** product cards opened the detail modal from a `click` handler on a plain `<div>`: not focusable, not announced as interactive, not operable by keyboard.
**Changed:** added `role="button"`, `tabindex="0"`, a descriptive `aria-label`, and an `onkeydown` handler for Enter and Space.

### 20. FAQ accordions did not announce their state — `help.html` — **Medium**
**Wrong:** the FAQ toggle was a `<button>` without `type` (so it would submit inside a form context) and without `aria-expanded`, so assistive tech could not tell open from closed.
**Changed:** added `type="button"` and `aria-expanded="false"`, and `toggleFaq` now updates `aria-expanded` on both the open and close paths.

### 21. Unlabelled icon share button — `article.html` — **Low**
**Wrong:** the share button had no `type` and no accessible label.
**Changed:** added `type="button"` and `aria-label="Copy a link to this article"`.

### 22. Banner and modal accessibility gaps — `nations.js`, `news.js`, `archive.js` — **Low**
**Wrong:** dismissible banners and detail modals lacked semantic roles and keyboard affordances.
**Changed:** added the appropriate `role`/`aria-*` attributes and `type="button"` on controls, matching the already-correct pattern in `economy.js`.
