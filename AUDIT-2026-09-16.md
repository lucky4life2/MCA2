# Compliance & Accessibility Pass — 2026-09-16

**Scope:** the 20-item compliance/accessibility checklist supplied for this session, run against the entire static front end. Builds on the prior security/UX audits (`AUDIT-2026-08-30.md`, `AUDIT-2026-09-01.md`) and the COPPA effort (`PHASE1-AUDIT-COPPA.md`, `LEGAL-REVIEW-NEEDED.md`, `SECURITY-PROGRAM.md`), all of which were re-verified rather than re-done from scratch.

**New since the last audit:** the Shop (`shop.html`) now has a live Stripe Checkout integration (`createCheckoutSession` in `supabase.js`) for one-time merchandise and a $12/yr membership subscription, with `orders`/`membership_status` tracked in `account.html`. This is real payment processing that didn't exist when `PHASE1-AUDIT-COPPA.md` was written (it described checkout as a disabled placeholder) — several fixes below exist specifically because of this.

## Fixed this session

1. **Privacy policy** — already thorough (`privacy.html`); added the missing disclosure that **Stripe** processes Shop/membership payments (it wasn't listed anywhere despite being live), plus a payment-information collection paragraph and a cross-link to the new Cookie Policy.
2. **Terms of service** — added a "Purchases & Subscriptions" section (`terms.html`) disclosing Stripe, auto-renewal, cancel-anytime, and a link to the new Refund Policy — none of this existed even though the Shop already takes real payments.
3. **Refund policy** — didn't exist at all despite live Stripe payments. Added `refund.html` (membership cancellation terms, a 7-day/no-benefits-used full-refund window, merchandise defect/non-delivery terms) and linked it from the footer, Terms, and account page.
4. **Cookie policy** — only a one-line mention inside the Privacy Policy. Added a dedicated `cookies.html` itemizing exactly what's stored (auth session, theme, cart — all `localStorage`, all strictly necessary), confirming no advertising/analytics cookies exist, and linked it from the footer and Privacy Policy.
5. **Cookie consent banner** — none existed. Added an informational (not gating) dismissible banner in `nav.js`/`style.css`, since only strictly-necessary storage is used and there's nothing to block pending consent; it links to the new Cookie Policy and remembers dismissal in `localStorage`.
6. **Form consents** — re-verified: the signup Terms/Privacy checkbox (`login.html`) is unchecked by default and gates every signup path; `news_email_opt_in` defaults `false` (opt-in, not pre-checked); no other form pre-ticks a marketing consent. No changes needed.
7. **No unnecessary data** — re-verified against `PHASE1-AUDIT-COPPA.md`'s inventory; still minimal (no phone/address/biometric/geolocation collection). No changes needed.
8. **Third-party SDK audit** — re-verified the list in `AUDIT-2026-09-01.md` and added the one that changed: **Stripe** is now a live third party receiving payment data (see #1). No tracking/analytics SDKs found anywhere (`grep` for Google Analytics, GTM, Meta Pixel, Hotjar, Segment, Mixpanel, Plausible — zero matches).
9. **Dark patterns** — the real gap was that an active $12/yr subscription had **no visible way to cancel** (no Stripe customer portal, no cancel button anywhere) — a negative-option/forced-continuity risk. Added a "Cancel Membership" button on `account.html` that pre-fills and opens the existing staff-message form (one click to send a cancellation request staff can action in Stripe), and documented the process in the new Refund Policy. No confirmshaming, forced continuity language, or hidden opt-outs found elsewhere.
10. **Hidden fees** — re-checked `shop.html`'s pricing rendering (`priceLabel()`): full price and billing cadence are always shown up front, before add-to-cart. No fee/tax/shipping surprise fields exist in the product schema referenced by the front end. Terms now explicitly states prices are shown before any applicable taxes.
11. **Fake reviews** — none exist anywhere in the codebase (no review/rating/testimonial feature at all). Nothing to remove.
12. **Unsupported claims** — grepped for superlative/marketing-claim language ("guaranteed," "#1," "clinically," "as seen on," etc.) site-wide — no matches. Nothing to remove.
13. **Accessibility: alt text** — audited every `<img>` tag across all `.html`/`.js` files; all have meaningful `alt` text already (a couple of grep false-positives on multi-line template literals were checked by hand and are fine). No changes needed.
14. **Color contrast** — `--muted: #888888` (light mode) against the white/near-white backgrounds it's used on for body-size secondary text measured ~3.9:1, below the WCAG AA 4.5:1 threshold for normal text. Changed to `#6b7280` (~4.8:1). Dark-mode `--muted` was already compliant (~5.7:1) and untouched. Spot-checked other hardcoded text colors (e.g. the `#c0392b` "pending" red) — already compliant.
15. **Keyboard navigation** — found several `<div>`/`<span>` elements with `onclick` but no keyboard path (not focusable, no `Enter`/`Space` handling, no `role`): the public Nations grid (`nations.js`), task rows/cards/collapsed-chips (`tasks.html`), the account-page message-thread toggle (`account.html`), and eight admin-console elements (`admin.html`: dashboard stat shortcuts, role-badge overflow toggles, the role-assignment popup list, the nation-owner picker list, message-thread toggles, and audit-log row expanders). Added `tabindex="0"`, an appropriate `role`, and an `onkeydown` handler (Enter/Space) to every one, matching the pattern already established for the Shop product cards in the prior audit.
16. **Business details** — footer already names the org and has a working contact method; added an explicit "volunteer-run, non-commercial community club" line to the footer disclaimer for clarity, matching the existing Terms of Service language.
17. **Age consent for kids' data (COPPA)** — re-verified the Phase 2 implementation described in `privacy.html`'s "Children's Privacy" section (restricted-state accounts, RLS-enforced blocking, email-plus consent, parent portal) is present and internally consistent. No changes needed; see `LEGAL-REVIEW-NEEDED.md` for the standing attorney-judgment items, which are unaffected by this pass.
18. **Unsubscribe link in emails** — the actual email HTML is generated by Edge Functions (`notify-news-subscribers`, `email-member`) deployed outside this repository and couldn't be edited or fully verified here. What this pass *can* confirm: `account.html` already has a working, easy-to-find, self-service opt-out (the "News email" toggle, off by default), which is the mechanism any unsubscribe link should point to. **Action needed from the site owner:** confirm the Resend email templates for `notify-news-subscribers` actually include a visible unsubscribe/preferences link (ideally pointing to `account.html`) in the email body/footer, since that can't be verified from this repo.
19. **Font/image licensing** — the only externally-loaded asset is Google Fonts' "Open Sans" via `fonts.googleapis.com`, which is licensed for this exact use (SIL Open Font License, served directly by Google). All other images (`/images/`) are site-original assets (logos, flags, screenshots) with no third-party/stock naming or watermarks found. No changes needed.
20. **Data deletion request** — re-verified the existing self-service flow (`account.html`'s "Delete My Account" → 7-day scheduled deletion, re-verification required) is present, easy to find, and already documented in the Privacy Policy. No changes needed.

# Bug hunt — same date, separate pass

A deliberate hunt for correctness bugs (not compliance, not the already-swept
XSS/authorization surface) across the whole front end. Everything below was
verified by reading the code — and, where the answer depended on the database,
by querying the live schema — rather than taken on inspection alone.

## Fixed

**Money and irreversible actions**
1. **Marks could be sent to the wrong player.** `economy.page.js` resolved the recipient with `.ilike('username', typedName)`. `_` is legal in usernames *and* is LIKE's single-character wildcard, so "bob_smith" also matched "bob1smith", and `.limit(1)` with no `ORDER BY` picked whichever row came back first. The confirm dialog echoed what you typed, never what it resolved to, and `economy_transfer` is final. Typing a bare `%` matched every user. Added a `likeEscape()` helper to `economy.js`, an exact-match guard on the returned row, and the dialog now shows the resolved username. The same lookup granted **company officer powers** in `stocks.page.js` — fixed identically.
2. **Same wildcard bug in two "is this name taken?" checks** (`account.html`, site username and Minecraft username). It wrongly rejected free usernames containing `_`, and when the wildcard matched 2+ rows `maybeSingle()` returned null, letting a real duplicate through. Escaped both.
3. **A subscription could be checked out with quantity 2+.** `shop.html` incremented quantity for any repeat add with no product-type check, and the cart drawer showed +/− controls on subscription rows — so clicking "Subscribe" twice billed $24/yr recurring for one $12/yr membership. Quantity is now pinned to 1 for subscriptions and the controls are hidden.
4. **Returning from Stripe wiped the cart repeatedly.** `init()` is re-run on every auth event (`SIGNED_IN`, `TOKEN_REFRESHED`, `INITIAL_SESSION`) and `_checkoutReturn` was never cleared, so the "Payment received!" alert fired once per event and each re-run called `saveCart([])` again — deleting anything added since paying. Made the Stripe return one-shot.
5. **Double-clicking Publish published two articles and sent two email blasts** to every subscriber (the generated slug carries a timestamp, so no unique constraint caught it). Added an in-flight guard. Same guard added to the dividend flow in `stocks.page.js`, where a double-click proposed *and paid* two dividends out of a company account.
6. **Adopting a recusal motion in Congress recused the chair**, not the member who moved to be recused (`_me.id` instead of the motion's `raised_by`). `court.page.js` already did this correctly, which confirms the intent.
7. **An open amendment vote hijacked the measure's passage vote.** `congress.page.js` picked "any open roll call" for the measure's vote block, so Close Voting and Certify acted on the amendment's roll call while the modal still showed the passage question.

**Site-wide availability**
8. **A stalled network left every page permanently blank.** `nav.js` hides `<html>` immediately and only restores visibility after two sequential Supabase fetches. Neither had a timeout, and `fetch` doesn't reject on a *stalled* connection (captive portal, blackholed DNS) — only on a failed one, which is why the "fails open on a network hiccup" comment wasn't true in practice. Added a 6s timeout to both plus a 14s last-resort failsafe that always reveals the page.
9. **"Resend code" during signup was 100% broken.** It referenced a `SUPABASE_URL` that is `const`-scoped inside four *other* handlers, so it threw a `ReferenceError` on every click, caught by its own `catch`, always reporting a connection failure. It was also missing the `apikey` header. A user whose code expired or never arrived had no way to recover.
10. **The signup Verify button could stick disabled forever** — no `try/catch` around the fetch, JSON parse, or `setSession`, so any blip left it on "Verifying…" until a reload.

**Correctness / UX**
11. Paying members were told **"Not a Member — Join Now"** whenever `membership_current_period_end` was null, unparseable, or briefly stale after a renewal — from where they could buy a second subscription. Membership now follows the Stripe-synced status; a cancelled-but-still-covered member is also told when their access actually ends.
12. An orders query **failure** rendered as "No orders yet", telling a paying member their history was empty.
13. `_italic_` markdown ate **intraword underscores**, so `server_config_backup.yml` rendered as `server<em>config</em>backup.yml`. Fixed in all three renderers together (`article.page.js`, `news.js`, and the author's live preview in `news-publish.html`) so preview and published output still agree.
14. Nation owners **didn't see their Edit button** if they clicked into their own nation quickly — the ownership lookup only started after the grid was already rendered and clickable. It now runs concurrently and re-renders an open detail once rights are known.
15. The product editor **blanked legitimate zero values** (`|| ''`), so editing an out-of-stock or free product showed empty fields and then failed to save as "required".
16. **Rejecting an article couldn't be cancelled** — the note prompt was the only gate and `|| null` swallowed the Cancel, sending the article back to draft anyway. (`rejectCompany` two functions away already handled this correctly.)
17. A task comment was **silently discarded** on an RLS or network error — the insert result was ignored and the box cleared regardless.
18. `contrastText()` returned white for any **3-digit hex** colour (`substring(4,6)` → NaN), making light-coloured task tags unreadable. `safeColor()` allows 3-digit hex, so this was reachable.
19. Deleting a task status that was still in use surfaced a **raw Postgres foreign-key error**; it now explains what to do. (The code comment claimed it rewrote every task's `tag_id` — querying the live schema showed the FK is `ON DELETE NO ACTION`, so it never did and never could. Comment corrected.)
20. Guarded an unprotected `localStorage` write in `saveCart()` that made "Add to Cart" look like a dead button when storage is blocked.

## Found and deliberately not changed

- **`orders.amount_total` units are unverified.** `account.html` renders it as `$${amount.toFixed(2)}`, but Stripe reports `amount_total` in minor units — if the webhook stores it verbatim, a $12.00 order displays as "$1200.00". The `orders` table is currently **empty (0 rows)**, and the webhook lives in an Edge Function outside this repo, so there's nothing to confirm against. Guessing either way would be wrong: **please check the webhook before the first real order.**
- **`approveCompany`'s Cancel-on-note behaviour was left alone.** Unlike `rejectArticle`, it has a separate `confirm()` gate first, so treating Cancel on the optional-note prompt as "skip the note" is defensible rather than a bug.
- The cart stores a **frozen snapshot** of each product, so a price the admin changes afterwards stays stale in the drawer (Stripe still charges the current price), and quantity isn't capped by inventory. Fixing this properly means reconciling the cart against live product rows — a bigger change than this pass should make unreviewed.
- Several **lower-severity findings** were logged but not acted on to keep this diff reviewable: admin member filters resetting after an action, in-progress message replies being destroyed by a re-render, audit-log filter changes dropped while a query is in flight, duplicated audit dropdown options, audit rows collapsing on "Load More", and the unread badge counting threads in one place and items in another.
